# Images

## Our renders — committed

Generated by [`../render/vezha-massing.py`](../render/vezha-massing.py) from
the dimensions in the handoff docs. Regenerate with:

```sh
blender --background --python handoff/render/vezha-massing.py
# Blender writes PNG; these are committed as JPEG to keep the repo small
cd handoff/img && for f in vezha-*.png; do
  magick "$f" -strip -resize '1600x1600>' -quality 90 "${f%.png}.jpg" && rm "$f"
done
```

| File | View |
|---|---|
| `vezha-exterior.jpg` | Front three-quarter — cap, OLED window, surface grooves, strap slot, foot |
| `vezha-rear.jpg` | Rear three-quarter — service panel, cap screws, fan vents |
| `vezha-ghost.jpg` | Transparent shell over the internals |
| `vezha-exploded.jpg` | The depth stack, labelled, front to rear |

> [!IMPORTANT]
> **These are massing models, not CAD.** Every dimension traces to the docs,
> but no fillet radii, wall drafts, boss positions, connector cutouts or
> tolerances are real. They exist to make proportions and the depth stack
> legible — do not measure off them.

What the reference is for: **curved features, strap slots, textured surface
lines.** Shots that show those three clearly are the useful ones.

## Before committing anyone else's photos

> [!IMPORTANT]
> **The model's license has not been checked.** Printables listings carry a
> per-model license — some permit reuse with attribution, some do not permit
> redistribution at all. Open the listing, read the license field, and only
> commit the author's photos if it allows it. Credit **Alley Cat** and link
> the listing either way.
>
> If the license does not allow it, the link alone is enough — the written
> description in
> [Aesthetics and design](../README.md#aesthetics-and-design) carries the
> intent without the pictures.

Photos of **our own** prints have no such problem. Once the first shells come
off the printer, those are the better reference anyway.
